# YourBloom — подключение заявок

Код формы и серверный обработчик готовы. Без подтверждённой конфигурации форма не принимает заявки и предлагает существующий email. Никаких тестовых сообщений в реальный Telegram автоматически не отправлялось.

## Что нужно владельцу

Создать отдельного бота в официальном BotFather или выбрать существующего бота. Открыть его в своём Telegram и нажать Start. Подтвердить числовой chat_id личного чата, в который должны приходить заявки. Имя @username личного профиля не заменяет chat_id для этой отправки.

Не отправлять токен бота в чат ChatGPT, не вставлять в HTML/JavaScript, файлы GitHub, URL сайта или скриншоты.

В Cloudflare открыть существующий Worker `sweet-block-3530`, затем Settings → Variables and Secrets. Добавить:

| Переменная | Тип | Значение |
| --- | --- | --- |
| YOURBLOOM_TELEGRAM_BOT_TOKEN | Secret | Токен выбранного бота |
| YOURBLOOM_TELEGRAM_CHAT_ID | Secret | Подтверждённый числовой ID нужного чата |
| YOURBLOOM_ENQUIRIES_ENABLED | Plain text или Secret | `true`, только после проверки обоих значений |

Сохранить через Deploy. `keep_vars: true` сохраняет настройки dashboard при следующих GitHub-публикациях. Секреты в репозитории не хранятся.

После настройки отправить одну явно тестовую заявку с вымышленными данными, подтвердить её получение в нужном Telegram и проверить состояния успеха и ошибки. До реального теста нельзя утверждать, что сообщения доходят. Для остановки приёма заявок установить YOURBLOOM_ENQUIRIES_ENABLED в `false` и выполнить Deploy.

## Работа обработчика

POST `/api/partnership-enquiry` отправляет все заполненные поля выбранного типа обращения одним текстовым сообщением. GET `/api/partnership-enquiry/config` сообщает только доступность формы, без токена и адресата.

Проверяются источник запроса, тип и размер тела, обязательные поля, URL, подтверждение privacy и совершеннолетие авторов. Есть скрытое поле для защиты от простых ботов, лимит частоты по IP и общий лимит. Ограничения Cloudflare приблизительные и применяются отдельно по расположению сервера. Это базовая защита, а не гарантия отсутствия спама.

Суммарно слишком длинная заявка отклоняется с просьбой сократить текст; данные не обрезаются молча. Успех возвращается только после подтверждения Telegram для настроенного чата. При неопределённом результате автоматического повтора нет, чтобы не создавать дубли.

Обработчик не пишет в Google Sheets и не добавляет базу данных. Старые файлы курса, каталога и обработчиков сохранены. Новая функция вызывается первой только для двух новых адресов; другие запросы делегируются существующей выдаче статических ресурсов.

## Проверки

`node --test tests/enquiries.test.mjs` проверяет обработчик с подставным Telegram: реальной отправки и обращения к рабочей базе нет. Дополнительный сервер `tools/qa-server.mjs` используется только локально для проверки интерфейса и не входит в production-код.

Серверный код, тесты и документация исключены из выдачи статических файлов через `.assetsignore`.
